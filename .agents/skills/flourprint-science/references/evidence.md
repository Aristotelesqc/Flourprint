# Extraction and reproducibility

Use the existing data-record schema where one exists. These are review fields, not a new persisted
application schema or replacement for `docs/science/README.md`.
Describe snippet-only access explicitly in the record's notes/read-status conventions and keep
verification false. Do not add a new enum value to an existing data schema just because an access
description below uses that word.

A source record needs enough detail to trace a claim:

- author/title/date, DOI or stable original URL, and specific table/figure/passage;
- actual read status (full text, abstract, snippet or secondary transcription), who extracted it,
  access date and `source_verified` according to the existing records;
- provenance label from the science README, separately from access/verification status;
- original values/units, experimental material, control/treatment, sample/replicate information
  and uncertainty reported by the source; missing fields explicit;
- temperature location/profile, yeast type and dose denominator, ingredient/flour composition,
  geometry, measured observable and operational endpoint where relevant;
- conversions, transcription/digitization method and limitations, derived inputs and code;
- the specific Flourprint domain it supports, conflicts/caveats, and what it does not establish.

Recipe presets need exact source variant, ingredient quantities/denominators and method, plus any
editorial adaptation. A published time/temperature is a prescription unless a measured validation
is actually reported. Original source attribution remains separate from cross-source consensus.

## Common evidence failures

| Observation                                                     | Appropriate treatment                                                                                             |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Only a search excerpt/abstract was accessible                   | Cite actual access and limit conclusions; do not set full-text/source verification.                               |
| A blog quotes a paper's table                                   | Preserve secondary transcription status and trace the original; repeated quotations are not separate experiments. |
| A calculator/table is generated by a model                      | Keep MODEL OUTPUT, not measured dough data.                                                                       |
| Ambient temperature is reported but dough temperature is absent | Retain the missing distinction; any thermal conversion is a separate assumption/model.                            |
| Sugar/acid/egg effects differ by regime                         | Identify dose, process and endpoint; do not produce an unconditional acceleration/retardation rule.               |
| A fit has a small residual on few points                        | Report sample/domain and fit limitations; do not invent a predictive confidence band.                             |
| Sources use different endpoints                                 | Compare definitions first; do not average their durations as interchangeable outcomes.                            |

Reproducible work cites the retained input data and script command, parameters, conversions and
outputs with their units. Existing `docs/science/scripts/` is independent of the application;
inspect and reuse relevant scripts rather than manufacturing data to match the current engine.
