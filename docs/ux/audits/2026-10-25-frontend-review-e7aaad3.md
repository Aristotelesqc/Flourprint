# Frontend-quality review, PR #133 at e7aaad3 (read-only; engine/contract wiring excluded)

Method: static reading of the diff vs origin/dev (209 files, ~37k lines), ADR 0020/0021, sourcing inventory, DESIGN.md, packages/ui, the mockup, apps/mobile config, plus scripted checks (undefined CSS variables, dead CSS classes). Nothing was built or rendered. Findings marked (static) are derived from CSS/TSX reading, not observed in a browser.
Paths: M = docs/mockups/0.3-ux/src, U = packages/ui/src.

## Verdict

Not mergeable as "production-ready UI"; acceptable as a disposable review mockup only if the shared-library leaks are fixed or labelled. Component _composition_ in the mockup is good (screens use fp.\* almost everywhere). The weaknesses are (a) packages/ui is not safe to load into apps/mobile, (b) a parallel i18n system, (c) very large components with effect-driven state, (d) CSS token hygiene with at least one real dark-theme defect.

Counts: blocker 2, major 12, minor 10, nit 5.

## Styling approach per surface

- apps/mobile: Ionic 9 + Tailwind v4 (`@tailwindcss/vite`), no Preflight, layers `ionic, theme, base, components, utilities`, own `--color-*` @theme tokens (apps/mobile/src/theme/app.css:1-30), react-intl (ADR 0009).
- packages/ui: neither. Plain per-version CSS keyed on `[data-fp-component][data-fp-version]` + `--fp-*` tokens (generated tokens.css) + a second alias vocabulary in components.css:3-57 (`--color-ink`, `--radius-card`, `--type-label`...). No Ionic import anywhere (only a comment, U/motion.ts:178). No Tailwind.
- Mockup: plain CSS (layout.css etc.) + 120+ inline `style={{}}` objects + the library CSS. No Tailwind, no Ionic.
- Consequence for the port: nothing in the mockup's styling is Tailwind, so there is no "class soup" to dedupe, but also no mechanical path: screen CSS and inline styles must be re-expressed as Tailwind utilities (acceptable, mapped onto @theme tokens), and the library CSS cannot be dropped into the app as it stands (see B1).

## Blockers

**B1. components.css is a global, unscoped stylesheet that will restyle the whole app (U/components.css).**
It contains `* {box-sizing}` (:94), bare element rules `input:not([type=checkbox]), select, textarea` (:208), `h2`/`h3`/`p`/`small`/`button`/`fieldset` (:225-300), generic classes `.row .stack .surface .muted .actions .sr-only .segmented .seg-btn .field-label` (:108-203, :352), and screen-specific classes `.journal .draft-status .build-id-chip .incorporation .error-banner .preparation-instruction .quick-actions .timeline-axis .prep-conditions`. styles.test.ts only checks `v*.css`, so this file escapes the "scoped to id+version" rule that the README claims.
Consequences: (1) unlayered CSS beats every layer in apps/mobile's `@layer ionic, ..., utilities` cascade, so these rules override Tailwind utilities and Ionic, not the other way round; (2) `.sr-only` collides with Tailwind's; (3) the `:root,[data-theme]` alias block (:2-57) redefines `--color-surface`, `--color-surface-container-high`, `--color-bg`... which the app also defines in @theme/app.css with different values (e.g. surface-container-high #eae5dc app vs #e7e3dc library), silently shifting app colours; (4) app uses `--spacing-touch: 3rem`, library 48px (DESIGN.md admits it). Fix: move the structural classes into the owning version CSS (scoped), delete mockup-only classes, put tokens under `@layer`, and drop the second alias vocabulary or generate it from tokens.ts.

**B2. Library tokens that do not exist, so themed surfaces render with hard-coded light colours (static): M/recipe-history.css.**
`--fp-color-text`, `--fp-color-text-muted`, `--fp-radius-m` are never defined (script check). Fallback-only names `--fp-surface-0/1/2`, `--fp-color-border`, `--fp-color-accent-dim` always take their fallbacks. Result: `.history-dialog-input` (:160-166) is `#fff` with inherited (light) text in Dark/AMOLED, i.e. likely unreadable; banners use `#dc3545` and amber rgba (:16-35); radii are 0 (`--fp-radius-m`). Same class of defect: `--color-error` (U/components/sortable-list/v1.css:72,88,89,102 and M/RecipeView.tsx:1166) does not exist (real names `--color-danger`/`--fp-color-error`), so the drop-refusal cue is always `#ba1a1a` (poor contrast on dark surfaces), and `--shadow-high`, `--radius-lg`, `--fp-space-0-5` are undefined. recipe-history.spec.mjs never opens the history in Dark/AMOLED, so nothing catches it. Also `var(--color-error)` on RecipeView:1166 yields no colour at all.

## Major

**M1. Sourcing order not followed and undocumented (ADR 0021 layer 2, inventory rows 99-101).** Inventory/ADR say sheets=IonModal, menu=IonPopover, confirm=useIonAlert, checkbox/accordion=Ionic. fp.bottom-sheet, fp.floating-menu (U/components/use-dialog.ts, bottom-sheet/v1.tsx, floating-menu/v1.tsx) are native `<dialog>` + a 241-line hand-written controller (positioning, focus return, cloneNode "ghost" exit). ADR 0021 does allow #133 v1 on the ADR 0020 foundation, but no ADR/inventory addendum records why Ionic was not used (the dnd-kit exception _is_ documented: docs/architecture/2026-10-21-step-drag-behaviour.md). Consequence: Android hardware Back, keyboard avoidance and safe-area (no `env(safe-area-inset-*)` anywhere in packages/ui) are unhandled; DESIGN.md itself says these need native evidence. Document it, or record as a known divergence in the guides (guides do not mention Ionic at all except icon).
**M2. Parallel i18n system (M/messages.ts + 11 `*-copy.ts`, ~1,900 lines, 669 `t(locale,..)`-style call sites).** `[fr,en]` tuples and `locale==='fr' ? ...` ternaries (messages.ts:590-606, `percent`, `colon`) instead of react-intl/ICU in apps/mobile/src/i18n (ADR 0009 mandates ICU, plurals, shared catalog + parity test). No plural handling anywhere. Consequence: every string must be migrated; the parity test and `use-messages` hook are bypassed; FR/EN grammar rules cannot be expressed.
**M3. String concatenation breaks grammar/locale.** `${count} ${t('stepsTab')}` as a noun (ProcessView.tsx:747,749, no plural: "1 Étapes"); French spaced colon hard-coded in templates: `${t('weighed')} : ${name}` (PreparationView.tsx:1313), `${t('editStep')} : ${title}` (ProcessView.tsx:960,977) renders "Weighed : x" in English; `${sign}${diff} min` hard-coded unit (preparation-runtime.ts:56); tab labels built by concatenation with counts/suffixes (App.tsx:960; PreparationView.tsx:647-656); hard-coded "FR / EN" label and aria-label (App.tsx:633-636); `` `${stepCopy('dragHandle')}${colon(locale)}${title}` `` (StepDrag.tsx:~150). Intl objects are re-created on every call (messages.ts:610-640).
**M4. God components with effect-driven state.** App() is one function of ~1,450 lines (M/App.tsx:117-1572, 23 useState, 8 effects, zero memo/context); PreparationView() ~1,370 lines, 29 useState (PreparationView.tsx:110-); RecipeIngredients ~1,000 lines (RecipeView.tsx:539-1535); ProcessView 1,729 lines. Modal open/close booleans (`outcomeOpen`, `durationOpen`, `refusalDialogOpen`, `correctTimeOpen`, `repeatStepOpen`... :125-150) should be one discriminated-union state or sub-components that own their state. Prop drilling is total: `store`, `locale` passed to every component; no context. Consequence: untestable, every state change re-renders the whole screen.
**M5. Countdown re-renders everything once per second.** `setNow(Date.now())` every 1000 ms in PreparationView (:159-163) and in App on the library (App.tsx:177-182) re-renders 1,400 lines of JSX, all sheets, journal and weighing list. No `memo`, no isolated `<Countdown>` subscribing to a tick. Also `useState(Date.now())` evaluates every render (:121; App.tsx:174). Fix: extract a `useNow()` consumed only by the timer subtree.
**M6. Reset-by-effect and event-handling-in-effect anti-patterns (React 19).** PreparationView.tsx:165-188 resets ~20 pieces of state in `useEffect([session?.id])` (renders once with stale state; should be `key={session.id}` on an inner component). ProcessView.tsx:775-781 `pendingMove` effect is an event handler in disguise. ProcessView.tsx:659-672 and :699-710 effects sync `editingStepId`/focus via state flags. App.tsx:226-239 effect deps include `params`, a fresh `URLSearchParams` each render, so it runs on every render; App.tsx:390-420 popstate effect has no deps array (re-subscribes every render, avoids stale closure by brute force); App.tsx:123-129 `useLayoutEffect` with `[]` writes state from the URL (should be initial state). No eslint-plugin-react-hooks and no jsx-a11y in the repo (eslint.config.js has neither), which is why none of this is flagged. Recommend adding both (incl. React 19 compiler rules).
**M7. Focus management by DOM query on test hooks and CSS classes.** ProcessView.tsx:666-669,699-710 focuses `[data-testid="step-menu-${id}"]` and `[data-step-id=..] .fp-drag-handle` via `querySelector`; production behaviour now depends on test ids. SectionCarousel.tsx:20-45 finds the tabs element by `querySelector('[data-fp-component="fp.tabs"], .section-tabs, [role=tablist]')` and U/section-carousel/v1.tsx:97-118 repeats a wider heuristic search and signals via a bubbling `CustomEvent('fp:tab-gesture')`. tabs/v1.tsx:166 focuses the next tab by `parentElement.querySelectorAll('button')[next]`. use-dialog.ts:21-37,60-72 duplicates opener-tracking logic with `closest('button,[role=button],a,...')`; RecipeView.tsx:555-575 re-implements the same focus-return again. Consequence: renaming a class or testid silently breaks focus/gestures; use refs/context (a `TabsContext` or a shared ref prop).
**M8. 48 px target is not enforced in shared CSS; the 40/48 toggle is partly fake.** Each component repeats `var(--fp-spacing-touch, 48px)` (≈15 files); prep-hero/v1.css:234-236 uses literal `48px`. `[data-target-size]` only sets `--touch-target` (components.css:59-64), which only weighing-checkbox/ingredient-row/`.check-option` read; buttons, icon-buttons, tabs, number-field always use `--fp-spacing-touch`. So `?targets=40` (README, owner choice "40/48") changes some controls only. Native `<select>`/`<input>` targets rely on a descendant rule of `fp.surface` (surface/v1.css:21-55) and so are 48 px only inside a Surface; headers' `fp-input-control` selects (App.tsx:613-783) depend on that. Tests assert the literal 48 (see T2) instead of reading the token.
**M9. Missing shared controls: ~23 native `<select>`, text inputs, textarea, `<details>`, drag-handle button, build label, toast are screen-local.** `<select>`: App.tsx:613-783 (8), ProcessView (7), PreparationView:1228,1254, RecipeView (2), DependencyEditor:146; `<input>` App.tsx:516,846, ProcessView (4), RecipeView (3), RecipeHistory:354; `<textarea>` PreparationView:1418; `<details className="template-details">` App.tsx:1473 beside the library's Disclosure; local `.fp-touch-refusal-toast` + scrim (ProcessView.tsx:1679-1695) beside `warning-banner`; local drag handle button (StepDrag.tsx:158) beside the fp.sortable-list handle; `build-label` button (App.tsx:1229, ADR lists it as custom, so should be an fp item); water-source stacked bar chart built from inline styles with raw hex colours `#9c4174`, `#5b631e` (RecipeView.tsx:304-420). No `fp.select`/`fp.text-field`/`fp.toast`, no ADR sourcing entry (Ionic `IonSelect`/`IonInput`/`IonToast` exist). Consequence: these will each be re-done in the port, and are styled by global `input,select` rules (B1).
**M10. Mockup/screen-specific content in packages/ui.** `fp.bottom-bar` variant `'A'|'B'` (props.ts BottomBarProps; bottom-bar/v1.tsx:18-28 class names `phone-footer`, `phone-bottom-nav`, `toolbar-B`) encodes the owner's nav A/B review choice; bottom-sheet CSS reads `--phone-width` (bottom-sheet/v1.css:40,116), a mockup phone-frame variable; use-dialog queries `[data-fp-overlay-boundary]` (mockup frame) and `.menu-popup`/`.modal-sheet` by class; ModalProps/MenuProps carry `previewTrigger` ("Catalogue only", props.ts), `SurfaceProps.componentId/componentVersion`, `dataTestId` on 6 components, `NumberFieldProps.locale: 'fr'|'en'`; prep-hero hard-codes `data-testid="prep-heading"`, `prep-step-line`; components.css journal/draft/build-id/incorporation (B1). ADR 0020 says the library must be display-ready and product-neutral.
**M11. Props API inconsistent / overlapping (props.ts).** ButtonProps extends `ButtonHTMLAttributes` while IconButtonProps is closed with `onClick: () => void` (no event, cannot stopPropagation) and no `className`; PreparationTimerProps has overlapping `remainingLabel`/`countdownLabel`/`progressLabel`/`labels.progress`; mixed `readonly` conventions (SectionCarouselProps/SortableListProps readonly, rest not); Tabs variants `underlined|pills|chips` mix three controls in one id; `reduced?: boolean` passed to the carousel by the consumer although `data-motion`/matchMedia is the documented source (SectionCarousel.tsx). NumberField parses/formats numbers itself (number-field/v1.tsx:7-26, `toString().replace('.',',')`, can emit exponent form) duplicating and diverging from apps/mobile/src/i18n/numbers.ts `parseDecimal` (which ignores spaces; library does not).
**M12. Tabs misused semantically (a11y).** `role=tablist/tab` is used for filter chips (App.tsx:946: "Tous (4)") and for the preparation switcher (PreparationView.tsx:643) with no `tabpanel`/`aria-controls` anywhere in the repo (grep); `<nav role="tablist">` replaces the nav landmark. Filters should be toggle buttons/radiogroup or Ionic segment. Consequence: screen readers announce "tab 1 of 4" with no panel.

## 1. Component library usage (summary)

Good: screens import typed facades (ui.tsx, components.tsx) over `<Ui component="fp.*">`; Button used 106× with consistent variants; 23 components all have guides, registry entries and CATALOGUE.md (tests enforce this); dnd-kit is justified in a dated doc. Gaps: M1, M9, M10, M11. Variant duplication: "Cancel/Close" is `quiet` (text) in dialogs (PreparationView.tsx:1144,1176; RecipeHistory:331,374), `secondary` pill in others (TrashView, ProcessView 1×), and "Add" is quiet at DependencyEditor.tsx:164 but primary elsewhere; `quiet` is used for 35+ actions of unequal importance, so hierarchy collapses. The mockup also bypasses the `@flourprint/ui` package: it imports `../../../../packages/ui/src/...` by relative path (library.ts, ui.manifest.ts, ui.tsx), so the documented consumer pattern (README "Using it from screens") is not what is exercised.

## 2. Styling summary

Tokens: tokens.ts is the single source and tokens.css is generated (good). But two un-generated alias vocabularies (components.css; app.css) and ~20 undefined variables with hard-coded fallbacks (B2). Theme: Light/Dark/AMOLED via `data-theme`, same attribute the app uses on :root (app.css:`:root[data-theme='light']`) with different variable names, so co-loading collides. Reduced motion: m4. Tailwind: not used in mockup or library; app theme tokens (`--color-accent`, `--color-ink`, `--color-line`) differ from library names (`--color-primary`, `--color-ink`, `--color-outline`), so a Tailwind `@theme` bridge from tokens.ts is needed (the ADR 0021 theme builder is the intended place, not yet built).

## 3. React practice: see M4-M7, M12, m6-m10.

Strong points: no conditional hooks found (early returns follow all hooks in the files inspected), cleanups present on intervals/listeners, controlled inputs with raw-text retention in NumberField, `useId` for labels, `role=alert` on errors, dialogs set aria-labelledby.

## 5. Tests (scripts/mockup-tests, 28 specs, ~6,000 lines)

- T1 (major). Role/label usage is decent (≈650 getByRole) but heavily mixed with CSS and test ids: 35% of specs use `locator('.class')` on internals (`.metric-tile`, `.metric-value`, `.phone-header`, `.ingredient-info`, `button.warning-banner-actionable`, `.phone-content`, `.step-more-actions`), ~330 testid uses, and hard-coded French/English strings with `locale === 'fr'` branches (summary-fit.spec.mjs:112-130). Class renames (like B1's cleanup) will break dozens of tests.
- T2 (major). Geometry thresholds: 48 is principled (DESIGN.md) but duplicated as a literal in ~25 places, not imported from tokens.ts (so the 40 px option or a token change cannot be tested); others are tuned numbers: card height `< 160`, editing row `< 240`, `.ingredient-info >= 120`, Division row `<= 96` (steps-variants.spec.mjs:~66), 4th card bottom `<` content bottom under a forced Verdana font (audit-font-density.spec.mjs:8-21,43-48), anchor gap `<= 16` (audit-library-corrections:35). They encode the current layout (named "audit-\*-corrections"), not a DESIGN.md rule; harmless CSS changes will fail them, and a regression within the slack passes.
- T3 (minor). Gesture timing assertions (`end.time - first.time < 50` flick, `> 500` slow; finalisation.spec.mjs:200-201) are CI-load sensitive; `page.clock.setFixedTime` is good.
- T4 (minor). Vacuous assertion (m1); no dark/AMOLED coverage for history (B2); countdown re-render performance untested; one `toBeCloseTo(distance,0)`.
- Positive: deterministic clock/locale/timezone in config, FR+EN and 3 themes in many specs, `capture=1&motion=reduce` removes animation flakiness.

## 6. Portability to apps/mobile

Ready as-is: tokens.ts/tokens.css generation, the library mechanism (versions, manifest, Slot, motion items, guides/CATALOGUE), prop-typed presentational components that are self-contained and Ionic-free (badge, metric-pill, surface, timeline, icon, warning-banner, hero-summary, recipe-card, ingredient-row, step-node, context-tiles) once their CSS is separated from components.css, the sortable-list adapter (dnd-kit confined to packages/ui) and the core wiring done by the mockup's model.ts.
Must be rewritten or reworked: (1) components.css (B1), (2) the whole i18n layer onto react-intl/ICU with plurals (M2/M3, ~670 call sites and 11 copy files), (3) screen composition files (App/RecipeView/ProcessView/PreparationView ~6,400 lines): they hold URL-param routing, `history.pushState`, `phone-frame` portals and studio controls that belong to the Ionic router in the app, so they need splitting into routed pages plus feature components (M4); (4) sheets/menus/alerts onto IonModal/IonPopover/useIonAlert or an explicit ADR (M1); (5) native selects/inputs/toast/details/build label into fp items (M9); (6) inline styles (~120) and layout.css into Tailwind utilities or fp item CSS; (7) imports from relative paths to `@flourprint/ui` and add the workspace dependency (apps/mobile has none today); (8) test suite: Playwright specs target mockup.html query params (`screen=`, `capture=1`, `width=`) and class internals, so they must be re-authored against apps/mobile's e2e harness. Roughly: the library mechanism and ~half of the components port; screens and copy do not.

4. Add eslint-plugin-react-hooks (+ jsx-a11y) and fix what it reports; split PreparationView/App; isolate the countdown.
5. Collapse the i18n approach onto react-intl before adding more copy files.
