📐 Proposed Additions to DESIGN.md (0.3.0 UX Foundations)

      

        This specification codifies the REM vs. PX unit boundary, semantic visual cues, bounded motion tokens (#130), and the Modular Component Registry rule.
      


      
1. Unit Discipline: rem vs. px (#120 N1 Larger Text Compliance)

      

        
          

            Category
            Mandatory Unit
            Canonical Tokens
            Forbidden Patterns
          

        
        
          

            Typography
            rem only
            --type-headline (1.375rem), --type-title (1.125rem), --type-section (1rem), --type-body (0.9375rem), --type-label (0.8125rem), --type-meta (0.75rem)
            Arbitrary pixel classes: text-[11px], text-[13px], text-[15px], text-[17px], text-[19px]
          

          

            Touch Targets & Rows
            rem only
            --touch-target: 2.75rem–3rem, --touch-row: 3.25rem, icons 0.95rem–1.2rem
            Fixed pixel heights (min-h-[48px], min-h-[52px]) or missing flex-shrink: 0 inside scroll containers
          

          

            Numeric Columns
            rem / minmax
            grid-template-columns: auto minmax(0, 1fr) 3.75rem 4.5rem
            Fixed pixel columns (72px 84px) that clip values at 125% text scale
          

          

            Phone Frame & Hairlines
            px only
            Desktop phone frame 412px × 915px (#118), test viewports 360px/393px, borders 1px/1.5px, radii 8px–24px
            Sizing the outer phone frame in rem (which would widen the simulated screen under larger text)
          

        
      


      
2. Purposeful Visual Semantics (#125)

      
    
        
  • No decorative icon spam: Do not prefix arbitrary form labels with emojis. Use understated monochrome SVG icons for core baking concepts (wheat ear for flour, scale for dough mass, water droplet for hydration, operation badges on timeline steps).
    • 
        
  • No misleading target gauges: Do not render a progress/target gauge on summary metrics unless backed by an explicit domain target.
    • 
        
  • Single completeness notice: Consolidate unknown ingredient property warnings into a single fp-warning-banner at the bottom of the summary card, distinguishing partial known sums from complete totals.
    • 
      


      
3. Bounded Production Motion (#130 / #73)

      
    
        
  • Surface & anchored menu transitions: 150ms cubic-bezier(0.2, 0, 0, 1) for floating menus, segmented pills, and weighing checkmarks.
    • 
        
  • Disclosure & bottom sheets: 220ms–260ms for step-group accordions (grid-template-rows: 0fr → 1fr) and M3 bottom sheets.
    • 
        
  • Reduced motion: Immediately collapse durations to 0ms under prefers-reduced-motion: reduce. Never animate numeric value changes or block user input behind a transition.
